# 巡展作品光照预算 Web 工作台

为巡展作品管理展期曝光预算的本地 Web 工具：Node.js + SQLite + 浏览器页面，单机本地运行。

- **作品维度**：录入展期曝光上限与既有累计量，实时显示已用 / 预占 / 余额（单位 lux·min）。
- **时段维度**：为展厅时段录入起止时间、照度（lux）和展出作品，按 **实际经过分钟 × 照度** 计算曝光。
- **多段照度**：实际照度随时间变化时，进行中时段可携带**多段**（每段含起止与非负照度）结算，按 **Σ(段分钟 × 段照度)** 求总曝光；各段须首尾衔接、无重叠并完整覆盖实际区间，否则整批拒绝。
- **分段更正**：已结束时段可按原实际起止提交**带理由的完整分段**更正（也可覆盖实际区间），记录更正前后曝光/时间与分段快照；新总量替换旧总量，不重复累计。
- **整批排期**：未开始时段在草稿中统一编辑后整批提交；同一作品时段重叠、或“已用 + 预占”超上限时 **拒绝整批**，逐条指出冲突作品与时段。
- **生命周期**：时段开始即冻结原排期并保留预占；结束时补记实际起止与照度（单一或多段），**实际曝光替换该时段预占**；结算/更正超量后按开始时间/编号顺序标出不可启动时段与缺口并禁止启动。
- **乐观并发**：所有调整（含多段结算与更正）携带当前版本号，过期版本返回 409 与最新预算；校验失败不改变结算与版本。

## 一键启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

启动后打开：

- **页面地址**：http://localhost:8080
- 初始化：首次启动自动建表并写入演示数据（3 件作品 + 已结束/进行中/未开始时段）。

如需更换宿主机端口：

```bash
PORT=9090 docker compose up -d --build   # 页面变为 http://localhost:9090
```

停止与重置初始数据：

```bash
docker compose down            # 停止，数据保留在命名卷中
docker compose down -v         # 同时删除数据卷，下次启动重新初始化
```

## 本地直接运行（需要 Node.js ≥ 20）

```bash
npm install
npm start
# 打开 http://localhost:8080
```

## 配置（环境变量）

| --- | --- | --- |

| `DB_PATH` | `./data/lightbudget.db`（Docker 内为 `/app/data/lightbudget.db`） | SQLite 数据库文件路径；文件不存在时自动建库并初始化 |

## 计算与校验规则

- **曝光量** = （结束 − 开始，分钟）× 照度 lux，单位 **lux·min**。
- **多段曝光量** = Σ 各段（段结束 − 段开始，分钟）× 段照度；分段须首尾衔接、无重叠且完整覆盖实际区间。
- **已用** = 作品既有累计量 + 所有已结束时段的**实际**曝光（多段结算/更正按分段总量，更正以新换旧、不重复累计）。
- **预占** = 进行中时段的（冻结）计划曝光 + 所有未开始时段的计划曝光之和。
- **余额** = 上限 − 已用 − 预占；余额为负即超量。
- 排期整批保存时校验：
  1. 时间格式合法、结束晚于开始、照度/累计量非负（无效时序或负值一律拒绝）；
  2. 同一作品在任意两个未开始时段、以及与进行中（冻结区间）/已结束（实际区间）时段之间不得重叠；
  3. 每件作品「既有 + 已结束实际 + 进行中预占 + 本批未开始预占」不得超过展期上限。
- 任一条不满足则整批不落库，响应中给出作品、冲突时段对或超量数值。
- **不可启动核算**：每次调整/启动/结算后，未开始时段按开始时间（再按编号）顺序尝试占用预算；任一关联作品余额不足即标记为“不可启动”并列出每件作品的可用余额、需求与缺口，启动接口对该时段返回 422。调整排期保存后自动重新核算。
- **并发版本**：每次成功变更版本号 +1。请求必须携带当前 `version`；不匹配时返回 `409 VERSION_STALE` 与最新完整预算，前端自动刷新后需重新调整提交。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 最新版本、作品预算汇总、全部时段（含 `actualSegments` 分段与 `corrections` 更正记录）及不可启动核算结果 |
| POST | `/api/artworks` | 录入作品（body 带 `version`） |
| PUT | `/api/artworks/:id` | 修改作品上限/既有量等 |
| DELETE | `/api/artworks/:id` | 删除作品（被时段引用时拒绝） |
| POST | `/api/schedule` | **整批替换未开始时段**（body：`{version, slots:[...]}`） |
| POST | `/api/slots/:id/start` | 启动时段：冻结原排期、保留预占 |
| POST | `/api/slots/:id/finish` | 结束补记（旧，保持可用）：`{actualStart, actualEnd, actualLux}`，实际曝光替换预占并重新核算 |
| POST | `/api/slots/:id/settle` | **多段照度结算**（进行中）：`{version, actualStart?, actualEnd?, segments:[{start,end,lux}]}` |
| POST | `/api/slots/:id/correct` | **已结束时段分段更正**：`{version, reason, actualStart?, actualEnd?, segments:[...]}` |

## 多段照度结算与更正（本轮新增）

适用场景：巡展时段的实际照度随时间变化（例如开灯/调灯/关灯、阴雨天切换补光），单一照度无法准确描述实际曝光。

**分段规则**（`segments` 数组，按段顺序提交，服务端会再按开始时间排序）：

- 至少 1 段；每段含 `start`、`end`（`YYYY-MM-DDTHH:mm`）与非负 `lux`；
- 段内结束必须晚于开始；
- 各段**首尾衔接、无重叠**：前一段结束 = 后一段开始；
- **完整覆盖实际区间**：首段开始 = 实际开始、末段结束 = 实际结束；
- 总曝光 = Σ(段分钟 × 段照度)，单位 lux·min。

任一条件不满足返回 `422 SEGMENTS_INVALID` 并在 `errors` 中逐段说明，**整批拒绝，结算与版本均不变**。

### 1) 进行中时段多段结算 `POST /api/slots/:id/settle`

- 必须携带当前 `version`，过期返回 `409 VERSION_STALE`（带最新 `state`）。
- `actualStart` / `actualEnd` 可省略：此时实际区间即“首段开始 ~ 末段结束”；提供时用于强校验覆盖范围。
- 仅 `running` 时段可调；成功后时段变为 `finished`，作品**已用**计入新总量，后续未开始时段的不可启动状态与缺口立即重算。
- 单段时返回的时段 `actualLux` 为该段照度（与旧 finish 一致）；多段时 `actualLux` 为 `null`，明细以 `actualSegments` 为准。

调用示例（curl）：

```bash
# 09:00–11:00 为 200 lux（120 分钟），11:00–13:00 调亮到 300 lux（120 分钟）
# 合计 = 120*200 + 120*300 = 60000 lux·min
curl -X POST http://localhost:8080/api/slots/2/settle \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 1,
    "segments": [
      { "start": "2026-09-30T09:00", "end": "2026-09-30T11:00", "lux": 200 },
      { "start": "2026-09-30T11:00", "end": "2026-09-30T13:00", "lux": 300 }
    ]
  }'
```

返回（节选）：完整 `state` + `justFinishedExposure` + `blockedAfterFinish` + `settledSegments`：

```json
{
  "version": 2,
  "justFinishedExposure": 60000,
  "blockedAfterFinish": [ /* 因此次结算变为不可启动的未开始时段（含缺口） */ ],
  "settledSegments": [
    { "index": 0, "start": "2026-09-30T09:00", "end": "2026-09-30T11:00", "lux": 200, "minutes": 120, "exposure": 24000 },
    { "index": 1, "start": "2026-09-30T11:00", "end": "2026-09-30T13:00", "lux": 300, "minutes": 120, "exposure": 36000 }
  ],
  "slots": [ /* … */ ], "artworks": [ /* … */ ]
}
```

分段不合法示例（有缺口）→ `422`：

```bash
curl -X POST http://localhost:8080/api/slots/2/settle \
  -H 'Content-Type: application/json' \
  -d '{ "version": 1, "segments": [
    { "start": "2026-09-30T09:00", "end": "2026-09-30T11:00", "lux": 200 },
    { "start": "2026-09-30T11:30", "end": "2026-09-30T13:00", "lux": 300 }
  ]}'
# { "error": { "code": "SEGMENTS_INVALID", ... },
#   "errors": ["第 1 段与第 2 段之间存在缺口，分段须首尾衔接"] }
```

### 2) 已结束时段分段更正 `POST /api/slots/:id/correct`

- 必须携带当前 `version` 与非空 `reason`（≤300 字）。
- 默认沿用原实际起止，此时提交分段必须完整覆盖原区间；勾选/传入 `actualStart`、`actualEnd` 可同时更正实际区间。
- **新总量替换旧总量，不重复累计**：每件关联作品的已用量按差额重算；后续时段不可启动状态与缺口同步重算。
- 每次更正写入一条流水（`slot.corrections`）：理由、时间、更正前后起止与曝光、更正前后分段快照。
- 仅 `finished` 时段可调；分段不合法 / 版本过期时原结算与版本均不变。

调用示例：

```bash
curl -X POST http://localhost:8080/api/slots/2/correct \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 2,
    "reason": "测光表复核：午后补光仅 150 lux",
    "segments": [
      { "start": "2026-09-30T09:00", "end": "2026-09-30T11:00", "lux": 100 },
      { "start": "2026-09-30T11:00", "end": "2026-09-30T13:00", "lux": 150 }
    ]
  }'
# 新总量 = 120*100 + 120*150 = 30000，替换旧的 60000
```

覆盖实际区间的更正（例如提前撤展，单段）：

```bash
curl -X POST http://localhost:8080/api/slots/2/correct \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 3,
    "reason": "补录：实际 09:30 即撤展",
    "actualStart": "2026-09-30T09:00",
    "actualEnd":   "2026-09-30T09:30",
    "segments": [
      { "start": "2026-09-30T09:00", "end": "2026-09-30T09:30", "lux": 120 }
    ]
  }'
```

### 3) 页面用法

- **进行中时段**：点「结束补记」，弹窗顶部切换 **单一照度结算 / 多段照度结算**；多段模式可增删分段、实时显示衔接校验与合计曝光。
- **已结束时段**：点「分段更正」，在弹窗中编辑完整分段（默认沿用原实际起止，可勾选覆盖）、填写理由后提交。
- **明细展示**：已结束行点「分段×N / 更正×N」展开，查看每段起止/照度/分钟/曝光与全部更正流水（理由、前后曝光与时间、前后分段对比）。
- 旧的单一照度接口 `POST /api/slots/:id/finish`（`actualStart`/`actualEnd`/`actualLux` 及返回语义）**保持完全可用**，并自动落一条等值分段。

## 快速体验超量拦截

初始演示数据以 2026-09-30 为当天，预算均充足。进入页面：

1. 对「一号厅 09:00–13:00（进行中）」点 **结束补记**；
2. 把实际照度改为 `300`（240 分钟 × 300 = 72000 lux·min），保存；
3. 后续二号厅时段会被标记为 **不可启动**，页面列出《山水轴》《星夜手稿》的缺口，启动按钮被禁止；
4. 在未开始排期草稿中缩短时长 / 降低照度 / 改展作品后 **整批校验并保存**，缺口消除即可重新启动。
